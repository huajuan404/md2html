02 · 核心特性

三个独立旋钮控制输出

逻辑

内容的骨架

先说什么、再说什么。

  • 原文顺序按 Markdown 原结构铺
  • 结果先行结论抽到顶上,证据后置
  • 时序展开背景 → 问题 → 方案 → 结果
密度

一屏装多少

怎么把内容铺进屏幕。

  • 宽松长滚动页,留白宽
  • 紧凑长滚动页,多栏分区
  • 一屏一页分页,一屏一个观点
主题

视觉风格

看起来什么风格。

  • 配色色系、强调色
  • 字体字族、字重
  • 形态圆角、阴影、间距

5 个核心选择

03 · 护城河

每个 HTML 区块都知道自己来自 Markdown 哪几段

点击右侧任一区块,左侧自动跳到对应源文本。这是同类工具不做的事——也是 md2html 的护城河。

01

AI 只在重排这一步参与

AI 的工作被严格限定为"读懂段落角色,塞进骨架对应区"。HTML 由确定性 renderer 产出,避免 AI 输出失控、source map 失守。

02

改错别字不触发 AI 重排

只有改变文档"形状"的编辑才触发。改个词、修标点—— AI 完全不参与,渲染稳定,不浪费 token。

04

UI 语言和内容语言独立

中文 Markdown 永远产出中文标签的 HTML,不管编辑器 UI 是中是英——导出 HTML 是给读者的,不是给编辑者的。

05

骨架产品团队预写,用户不参与

9 份骨架共同决定输出形态。用户只选预设或拨三轴,不需要懂"骨架"是什么。

05 · 适用人群

它是给谁的?

谁该用

  • 用 ChatGPT / Claude / Codex / Gemini 输出长 Markdown,想转成像样页面
  • 把研究笔记、推文整理、访谈记录、报告变成阅读页 / 简报 / 卡片流
  • 想保留 Markdown 可编辑性,希望输出不只是"文档预览"

谁不该用

  • 只需要普通 Markdown 编辑器——用 Typora / StackEdit 就好
  • 需要多人实时协作——本工具是单人本地优先
  • 需要手写 HTML/CSS 的前端开发者——本工具不让你编辑 HTML
06 · 怎么用

5 步走通

  1. 浏览器打开 md2html
  2. Markdown 粘到左侧,或上传 .md
  3. 工具栏选预设或独立调三轴
  4. 右侧实时显示;点节点高亮源文本
  5. 点下载,得到单文件 HTML
