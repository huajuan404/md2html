# ADR 0005: 骨架模板由产品团队预写，AI 只做"分类填空"

- 日期：2026-05-15
- 状态：Accepted
- 相关：ADR 0001（LLM 只在 buildRenderPlan）、ADR 0002（形状变化驱动重编译）、ADR 0003（source map 粒度）

## Context

走法 A（让 AI 完全自由决定页面有哪些区）有三个无法忽略的问题：

1. **不可测**：写不出"结果先行逻辑下页面必有结论区"这种自动化测试。
2. **AI 容易越权**：自由度越大越倾向自己造原文没有的章节，正好踩 PRD §9.1（"HTML 看起来很可信但其实是 AI 编的"）。
3. **不可回溯**：AI 给出诡异结构时没法定位是哪一步出问题。

走法 B（完全写死结构）的问题是文章短时硬塞空区难看。

调查（`docs/thread-tools-research-2026-05-14.md`）显示行业共识：

| 工具 | 骨架谁写 | 模板数量 |
|---|---|---|
| nexu-io/html-anything | 产品团队预写 | 75 套 |
| visual-explainer | 产品团队预写 | 按用途若干 |
| clockless-org/html-anything | 产品团队预写 | 17 套样式系统 |

普通用户不会自己写"页面骨架"，让他们写就是让他们写代码。骨架是产品的一部分，不是用户负担。

## Decision

**采用走法 C：主骨架由产品团队预写，AI 只做分类填空。**

### 骨架规模

- **9 份骨架配置**：3 种逻辑 × 3 种密度。
- 写法是配置文件（不是写死的 if-else），未来 v0.2+ 可扩展为模板插件市场。

### 骨架内容形态

每份骨架声明：

- 包含哪些"区"（标题区、结论区、证据区、背景区、问题区、方案区、结果区、附录区 等）。
- 每个区是**必有**还是**可选**。
- 可选区在何种条件下出现（如"目录区"在章节数 >= 4 时才出现）。
- 区之间的顺序。

### AI 的工作被严格限定为三件事

1. **分类**：把每个 Markdown 源块标注角色（结论 / 证据 / 背景 / 问题 / 方法 / 结果 / 其他）。
2. **分配**：按骨架声明把源块塞进对应的区。
3. **生成标签**：每个区的标题文字，用内容语言。

### AI 不能做的事

- 不能改变骨架声明的"区"的数量。
- 不能改变骨架声明的"区"的顺序。
- 不能创造新的"区"。
- 不能引入原文没有的内容。

违反任一条 → 非法响应 → 回落原文顺序逻辑（faithful）重新编译。

### "幻灯片"块从模型中删除

ARCHITECTURE §4.3 原本列了 `slide` 这种节点类型。本 ADR 删除它。

理由：

- "一屏一页"现在是密度的一个取值（`per-screen`），不是节点类型。
- 渲染器在密度 = `per-screen` 时，把现有节点用一层壳子包起来分页，等同幻灯片效果。
- 不需要单独的 `slide` 节点类型来表达这件事。

### AI 找不到目标内容时不硬塞

例如：用户选了"结果先行"，但 AI 在文章里没识别出明确结论段落。

- 处理方式：**跳过结论区，不展示**。
- 不要硬抓第一段顶替。
- 这是 PRD §9.1（AI 编内容）风险的直接对策——宁缺勿滥。

## Consequences

### 必须更新的文档

- `docs/PRD.md` §5.5：把 Faithful/Reader/Brief/Deck 四 mode 章节重组成"逻辑 + 密度 + 主题"的三轴段 + 命名预设映射表。
- `docs/PRD.md` §10 验收清单：把"支持 Faithful/Reader/Brief/Deck 四种模式"改为"支持 3 种逻辑、3 种密度、3 种主题，命名预设 Faithful/Reader/Brief/Deck"。
- `docs/ARCHITECTURE.md` §4.3：删除 `slide` 这个 RenderNodeKind。
- `docs/ARCHITECTURE.md` §6：整章重写为"骨架模板配置 + 密度修饰规则"，不再按 mode 分节。
- 新增 `src/skeletons/`（或类似目录）作为 9 份骨架配置的代码归属。

### 测试可以落地的硬不变量

- 给定逻辑 = `result-first`、密度 = `compact`，编译输出的 HTML 一定包含带 `data-render-node` 的标题区元素。
- 给定逻辑 = `result-first`、不论密度，证据区总是存在（除非 AI 把所有内容都判为结论）。
- 给定逻辑 = `none`、不论密度，输出区数量等于原 Markdown 的顶层章节数。

### 未来扩展不破坏 ADR

- v0.2+ 加"科研论文骨架"或"公关稿骨架"，只是往骨架配置目录加一份文件，不改 compiler 主链路。
- v0.2+ 加"骨架模板市场"，是把 9 份内置骨架的能力开放给第三方，不改架构。

## Alternatives Considered

### 走法 A：AI 完全自由决定页面结构

**否决理由**：见 Context 段三大问题（不可测、易越权、不可回溯）。

### 走法 B：完全写死结构，连可选区都不允许

**否决理由**：文章短时硬塞空区难看；不同密度下用户也希望看到不同的呈现。
